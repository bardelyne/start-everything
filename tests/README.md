# Development checks

- `node scripts/test-installed-scroll.mjs`: exercises the production inventory batch and scroll handlers with a real offscreen XAML ScrollViewer. It checks 20-at-a-time loading, preserving scroll position and existing controls, ignoring duplicate in-flight requests, resetting a changed filter, and filling a tall viewport after layout without extra scrolling. Its window never takes focus. It does not attach to Explorer or alter installed programs.

- `node scripts/test-settings-dispatch.mjs`: runs the production settings callback and helper message handler with a private message-only window. It verifies that catalog reads, refreshes and destruction stay on the owning thread, including queued settings changes during failed startup, a burst after destruction, and successful recreation. It touches no real app catalog, registry settings or search window.

- `node scripts/test-catalog-watch.mjs`: checks change-burst coalescing and the maximum refresh delay, then runs real registry, Store/MSIX and recursive shortcut listeners in a hidden native window. It changes only a private volatile test key and temporary shortcut directory, drains in-flight callbacks on shutdown, and verifies repeated enable/disable cycles. It never installs/removes an app or changes existing Start-menu shortcuts. Normal host access is required for registry/package notifications.

- `node scripts/test-app-card-pool.mjs`: runs the ordinary-card pool in its own hidden XAML island. It verifies stable visual/input bindings across changing results, hidden excess slots, current menu metadata and selection indices, installed badges, Settings/default/late icons, preserving unchanged menus, switching to rich cards and back, and rebuilding within a changed result limit. Its timing excludes physical display presentation.

- Installed-app tests also check exact registry identity and installation-folder forwarding, interactive uninstall command parsing, protected entries, MSI remove switches and rejected missing/remote targets. The temporary metadata fixture uses a uniquely named volatile key under `HKCU\Software\StartEverythingTests`, outside the real installed-app catalog, and deletes it afterward. It requires normal host registry access. No uninstaller is executed and no existing application is removed.

- Catalog merge checks cover differing product/shortcut captions, executables in `bin` subfolders, canonical paths and app-ID targets, several shortcuts to one file, ambiguous executables, folder boundaries, separate installations, shared roots and packages. They verify Playit's real registration merges into its existing shortcut when installed, while preserving its search alias and removal action.


- `node scripts/test-app-warmup.mjs`: checks shared immutable catalog snapshots, headless replacement builds, nonblocking reads during refresh, duplicate-start prevention, pending first-search queries, failure fallback, clean unload before any search window exists, cancellation of pending catalog work, destroying retained warmup buffers after the matching consumer joins, and taskbar readiness. Only native metadata warms automatically; XAML still starts on an explicit search request.

Run on Windows x64 with Windhawk's compiler installed. CXX can select another compatible compiler. The mod remains a standalone source file.

- node scripts/embed-locales.mjs --check: validates all language keys, placeholders and the generated catalog.
- node scripts/test-localization.mjs: compiles the production calculator, conversions and localization tables and runs their regression cases.
- node scripts/test-search-pipeline.mjs: runs the real app/file/background workers with deliberately blocked file, icon and catalog providers. It requires new app queries to publish within 100 ms during those blocks, verifies new catalog results appear without reopening search or typing again, preserves selection across silent refreshes, keeps live utility cards running, checks query revisions and launch identities, and confirms displayed files remain visible until a replacement is ready. It also verifies installed-only markers and safe destinations, plus name conflicts between Quick Tools and custom slash commands.
- node scripts/test-online-cards.mjs: tests the production command parser, duplicate-name error cards, header icons, provider response validation, cache limits, local amount calculations, automatic/manual location behavior, default-off online access, automatic debounced fetching (typing replaces pending lookups before HTTP, disabled cards cannot reach a provider, and speed tests remain manual), offline mode, same-query card updates, and stale-response rejection with fake providers. Speed cases also check simultaneous transfers, timed windows, partial downloads, acknowledged uploads, upload-body limit adaptation, separate bounded probe/bulk request pacing, adaptive timing and grace periods, acknowledgment draining against a known-rate simulated connection, numeric/date Retry-After instructions, stopping the whole group on a rate limit, and retries that send no traffic during cooldown. No network requests are made. Run the generated online-cards.exe with --live explicitly to check native HTTPS sample weather/currency/crypto queries using Baghdad as the weather city. --live-speed checks a 64 KiB download and synthetic upload; --measure-speed-small checks both parallel directions with a 4 MB cap; --measure-speed-timed checks native deadline cancellation with one second per direction; --measure-speed runs the production adaptive LibreSpeed measurement, including automatic server selection. Production tests have finite payload caps, including rejected uploads; metered/unknown-cost connections use smaller caps. Optional isolated timing probes can use their explicitly selected uncapped one-second window. These optional live checks make network requests.
- node scripts/test-weather-layout.mjs: measures the production weather timeline, circular speed-test card and resource graphs in their own hidden XAML island at narrow and normal panel widths. It checks the Today highlight, day order, bounded height, installed-only information badges, each speed-test phase, gaps in resource graphs and reuse of controls during live updates. Speedometer animation checks cover rising/falling values, interrupted updates, exact final readings, matching needle/arc positions, geometry reuse, scale expansion, phase changes and the reduced-motion fallback. It does not attach to Explorer or access the network. Online-card checks also cover renamed Unicode/IP commands, saved-list expansion, progressive completion, shared rates, partial failure, daily-array validation and localized Today labels.
- node scripts/test-hardware-cards.mjs: tests bounded histories, invalid readings, GPU aggregation across processes and engines, adapter-wide VRAM usage without duplicate/process double-counting, missing/zero memory readings, GB/MB formatting, font icons, live local resource samples, one-second updates, stopping when hidden or when the query changes, resuming with fresh baselines, and clean shutdown. No network requests or settings changes occur. Restricted environments can hide performance-counter providers; run the generated hardware-cards.exe with --require-counters from an ordinary unrestricted desktop process to require CPU/GPU/VRAM counter availability too.
- node scripts/test-material-capture.mjs: compiles production material capture/reconstruction code and tests native effects, non-owning caches, reused factory/brush identities (including failed and animated captures), current-load hidden brushes, passive capture of pre-existing visible/hidden brushes across enable/update cycles without invoking their lifecycle or changing their composition assignment, identity-checked reload recovery, corrupt/truncated/incompatible storage, changed public colors and native compositions, bounded eviction, storage failures, untouched host metadata, and cross-thread cleanup.

- node scripts/test-xaml-lifecycle.mjs: reproduces the lost XAML diagnostics subscription after a secondary island thread exits, then verifies the production shutdown drain across 12 reloads while another XAML thread stays alive. The negative control deliberately skips the drain and must reproduce a pending subscription.

The material suite runs in separate hidden processes with a fake in-memory Windhawk storage backend. Its test hooks apply only to those processes. A second process exits with populated material caches and live composition objects, deliberately skipping normal mod cleanup to exercise global destruction after the other threads terminate. The suite does not inject into Explorer or change Windhawk settings. The test runner embeds a Windows compatibility manifest into its own temporary executable so desktop XAML is available.

All test runners accept an output directory as their first argument. Results are saved there in results.log.

The lifecycle suite attaches its own diagnostic test DLL only to its own hidden test process. It never attaches to Explorer or changes installed mod settings. Each process has a timeout, and the surviving host remains alive during every secondary-thread reload.

- `node scripts/test-services.mjs`: checks command parsing, localization, duplicate names, service-name/description/status filtering, limits, action availability, shell-data encoding, native read-only service enumeration, asynchronous publishing and prompt worker shutdown. The generated `services.exe --helper-check` checks error propagation using a nonexistent service. Reading the local SCM requires normal host access; the restricted tool environment may deny it.
- `services.exe --fixture-check` is a separate administrator-only integration test. It creates a uniquely named, on-demand LocalService fixture from `service-fixture.exe`, tests Start/Restart/Stop through the production helper, checks the restarted PID, then stops and deletes only its own fixture. It never controls existing Windows services. The fixture has a two-minute lifetime backstop.

- `node scripts/test-installed-apps.mjs`: reads local Installed apps registrations and current-user packages, tests name/identity merging with real shell launch entries, preserves suite/version records, verifies management-only destinations and local-only icon paths, and confirms Microsoft 365 `en-us` is searchable when installed. Private GUI/console fixtures test missing-shortcut discovery, exact filenames/product metadata, ambiguous candidates, helpers, shared folders and package exclusions. These fixtures are inspected without running them; MSI Afterburner's actual launcher is checked when installed. The suite also checks hidden-app manifest display names, technical-name aliases, multi-app suite fallback, rejected DTD/truncated input, and real runtime logos at normal/high display scales. Add `--full-settings` after the output directory to include production Windows Settings discovery in the catalog and single-letter matching measurements; these timings exclude UI presentation. No app is launched or removed. Package metadata may be unavailable in a restricted environment; the generated executable can run from an ordinary desktop process for the full catalog.

Package-logo tests call the real MTA decoder from an STA caller. Catalog tests reject UNC/shell/URI targets before file-existence probes, and pre-cancelled rebuilds return before shell enumeration.

Service shutdown regression: `services.exe --exit-with-idle-worker` starts only a hidden idle reader and exits without a controlled mod unload, verifying that a joinable worker does not abort the process. It never enumerates, starts or stops a service. The default runner performs this check after its read-only enumeration suite. Speed tests also cover a cap reached before the grace period ends, returning a marked partial result rather than an error.
